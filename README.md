# assistant-low-vision-mobile

Мобильное приложение системы голосового описания сцены для людей с нарушениями зрения: по касанию снимает сцену камерой, по удержанию записывает вопрос и проигрывает ответ Шлюза голосом.

## Назначение

Приложение - клиент [Шлюза](https://github.com/nikarpoff/assistant-low-vision-platform) по протоколу `alv.v1` (WebSocket):
- касание экрана - описание сцены, удержание - вопрос голосом, свайп вверх - пассивный режим с предупреждениями об опасностях;
- ответ звучит голосом сервиса синтеза речи, системные фразы заранее записаны и лежат в приложении;
- экран для слабовидящих: чёрный фон, крупный белый и жёлтый текст;
- снимки и аудио живут только в памяти и никогда не пишутся на диск.

Требования - в [docs/spec.md](docs/spec.md).

Состояние: версия 0.1.0 в разработке. Работают жесты, камера, микрофон, сессия со Шлюзом, воспроизведение ответа, пассивный режим, экран для слабовидящих, TalkBack, настройки и отладочная панель. Ручные проверки на телефоне описываются в `docs/manual-tests.md`.

## Стек технологий

- **Язык**: Kotlin 2.4, Android 8.0+ (minSdk 26), targetSdk и compileSdk 37
- **Сборка**: Gradle 9.8 (Wrapper), Kotlin DSL, каталог версий `gradle/libs.versions.toml`, Android Gradle Plugin 9.5
- **Интерфейс**: Jetpack Compose (BOM 2026.09.00), Material 3
- **Камера**: CameraX, только анализ кадров
- **Сеть**: OkHttp (WebSocket), kotlinx.serialization
- **Настройки**: DataStore Preferences
- **Детектор речи**: WebRTC VAD `com.github.gkonovalov.android-vad:webrtc` (MIT, JitPack)
- **Тесты**: JUnit 4 на JVM

Google Play Services не используются: приложение работает и на устройствах без них.

## Сборка

Нужны JDK 17 и Android SDK с пакетами `platforms;android-37.0` и `build-tools;37.0.0`. На машине разработки их ставит `scripts/setup-dev-env.sh` из репозитория Шлюза, путь к SDK лежит в `local.properties` (файл вне git):

```properties
sdk.dir=/opt/android-sdk
```

Команды:

```bash
./gradlew testDebugUnitTest   # JVM-тесты
./gradlew lintDebug           # Android Lint, отчёт в app/build/reports/lint-results-debug.html
./gradlew assembleDebug       # APK в app/build/outputs/apk/debug/
./gradlew --stop              # остановить демон после работы
```

Те же три задачи выполняет CI на GitHub Actions (`.github/workflows/ci.yml`) на JDK 17.

### Значения по умолчанию

Адрес Шлюза и токен устройства по умолчанию задаются при сборке и попадают в `BuildConfig`. При первом запуске они становятся значениями настроек; дальше действует то, что сохранено на экране настроек.

| Свойство Gradle | Поле `BuildConfig` | Что это | Если не задано |
|---|---|---|---|
| `alvServerUrl` | `DEFAULT_SERVER_URL` | адрес Шлюза: `wss://<домен>` или полный `wss://<домен>/v1/session` | пусто: приложение не подключается, пока адрес не введён в настройках |
| `alvDeviceToken` | `DEFAULT_DEVICE_TOKEN` | токен устройства из `APP_DEVICE_TOKENS` Шлюза | пусто: заголовок `Authorization` не отправляется |

Токен - секрет, поэтому в git его нет. Свойства передаются в командной строке или лежат в `~/.gradle/gradle.properties`:

```bash
./gradlew assembleDebug -PalvServerUrl=wss://alv.example.org -PalvDeviceToken=<токен>
```

Адрес без пути дополняется `/v1/session`. Сертификат Шлюза проверяется по системным корневым сертификатам, пользовательские удостоверяющие центры не принимаются ни в одной сборке.

Только отладочная сборка разрешает открытый `ws://` к локальному стенду `compose.fake.yml` (`deployments/` Шлюза, порт 8080): к `10.0.2.2` из эмулятора и к `localhost` с телефона после `adb reverse tcp:8080 tcp:8080`. Например, `-PalvServerUrl=ws://10.0.2.2:8080`.

### Earcon

Звуки подтверждения жестов (`res/raw/earcon_*.wav`) генерирует `tools/earcons.py` из стандартной библиотеки Python:

```bash
python3 tools/earcons.py   # перезаписывает app/src/main/res/raw/earcon_*.wav
```

Системные фразы (`res/raw/phrase_*.wav`) готовит `tts-service` по списку `phrases/phrases.yaml`, команда - в заголовке этого файла.

### Память

Сборка рассчитана на машину с 3 ГБ ОЗУ. В `gradle.properties` проекта:

| Параметр | Значение | Зачем |
|---|---|---|
| `org.gradle.jvmargs` | `-Xmx1536m -XX:MaxMetaspaceSize=512m -Dfile.encoding=UTF-8` | потолок кучи демона Gradle |
| `org.gradle.workers.max` | `2` | не больше двух параллельных воркеров |
| `org.gradle.parallel` | `false` | модули собираются по очереди |
| `org.gradle.caching` | `true` | кэш сборки |
| `kotlin.daemon.jvmargs` | `-Xmx512m` | потолок кучи демона Kotlin |

Демон Gradle завершается после 10 минут простоя: `org.gradle.daemon.idletimeout=600000` в `~/.gradle/gradle.properties`.

## Управление

### Жесты

Весь экран - одна поверхность для жестов, мелких кнопок нет. Каждый жест подтверждается earcon и короткой вибрацией не позже 100 мс.

| Жест | Что делает |
|---|---|
| касание | описать сцену: снимок уходит на Шлюз, ответ звучит голосом |
| двойное касание | повторить последний ответ из памяти, без запроса к серверу |
| удержание | задать вопрос: запись идёт, пока палец на экране, со снимком в начале удержания |
| свайп вверх | включить или выключить пассивный режим, новое состояние звучит фразой |
| свайп вниз | прервать речь |

После ответа 5 секунд микрофон ждёт вопроса без жестов: достаточно заговорить. Голосовые команды повтора, остановки и переключения пассивного режима распознаёт Шлюз (PLT-4 в [docs/spec.md](docs/spec.md)), а выполняет приложение.

Пассивный режим при первом запуске выключен, дальше запоминается последний выбор. Пока он включён и приложение в ожидании, раз в 3 секунды (`passive_interval_ms` Шлюза) уходит снимок, и приложение предупреждает только об опасностях.

Без соединения жест сразу получает фразу «Нет связи с сервером», приложение переподключается само с паузами от 0,5 до 8 секунд.

### TalkBack

С включённым TalkBack экран - один элемент «Ассистент. Двойное касание - описать сцену»:
- двойное касание описывает сцену;
- двойное касание с удержанием задаёт вопрос, как удержание без TalkBack;
- в меню действий: «Задать вопрос» (микрофон ждёт речи и заканчивает вопрос по паузе), «Повторить», «Пассивный режим», «Стоп» и «Настройки».

Текст ответа на экране TalkBack не зачитывает: ответ уже звучит голосом приложения.

### Экран и настройки

Экран для слабовидящих: чёрный фон, белый и жёлтый текст не меньше 28 sp, контраст выше 7:1, портретная ориентация. Показаны состояние («Ожидание», «Слушаю», «Смотрю», «Говорю», «Нет связи») и текст последнего ответа. Пока приложение открыто, экран не гаснет.

Настройки открываются действием TalkBack «Настройки» или ярлыком «Настройки» по долгому нажатию на значок приложения:
- адрес сервера и токен устройства;
- пассивный режим;
- код участника испытаний (`label` в `hello`);
- отладочная панель: последнее E2E (`trigger_to_first_audio_ms`), метрики телефона, этапы Шлюза, задержка подтверждения жеста `confirm_ms` и запуска системного синтеза `tts_start_ms`.

Те же значения пишутся в отладочный журнал: `adb logcat -s alv`.

### Разрешения

Камера и микрофон запрашиваются при первом запуске. Перед системным запросом звучит объяснение, зачем они нужны. При отказе приложение голосом объясняет, как выдать разрешения в настройках телефона, и проверяет их снова при следующем открытии.

## Приватность

- Кадры камеры и аудио микрофона живут только в памяти до конца запроса: не пишутся на диск, во временные файлы, во внешнее хранилище и в `MediaStore`.
- Последний ответ для повтора (текст и звук) тоже хранится только в памяти.
- Настройки лежат в приватном хранилище приложения (DataStore). Устройство представляется случайным UUID, который создаётся при первом запуске; персональные данные не собираются.
- Резервное копирование данных приложения выключено. Сторонних SDK аналитики и рекламы нет.

## Структура

Код разложен по шаблону MVC внутри пакета `io.github.nikarpoff.alv`:

```
app/src/main/kotlin/io/github/nikarpoff/alv/
├── model/        # чистый Kotlin без android.*: автомат AssistantStateMachine, Scene, SceneObject,
│                 # Answer, Settings, кодек протокола, PlaybackClock, ClientMetricsBuilder
├── controller/   # AssistantController: жесты, микрофон, сессия и таймер → события автомата, действия;
│                 # CameraController, MicrophoneController, SessionController, SettingsRepository,
│                 # PassiveTimer и чистая логика: жесты, конец речи, размер кадра, переподключение
└── view/         # MainActivity, AssistantScreen, SettingsScreen, DebugPanel, AnswerPlayer,
                  # Feedback (earcon, вибрация, фразы), FallbackSpeech, Theme
tools/earcons.py  # генератор earcon
app/src/test/
├── kotlin/       # JVM-тесты Model и чистой логики контроллеров
└── resources/protocol/vectors.json   # вектора протокола, побайтная копия из репозитория Шлюза
```

Model не зависит от `android.*`, поэтому проверяется JVM-тестами без эмулятора.
